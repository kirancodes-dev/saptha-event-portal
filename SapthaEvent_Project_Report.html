Section 01
Platform Overview
What SapthaEvent is and what it does

What is SapthaEvent?

SapthaEvent is a complete college event management portal built for SNPSU. It handles the entire lifecycle of a college event — from creation and public listing, to participant registration with QR tickets, live scanning at the venue, real-time scoring for judged events, automated certificate generation, and post-event AI analytics. Every role in the event ecosystem has a dedicated dashboard with purpose-built tools.

Email & Notification System
8 automated email triggers keeping everyone informed

Dual Email Provider

The system auto-detects which provider to use: if RESEND_API_KEY is set it uses the Resend API, otherwise it falls back to Gmail SMTP via MAIL_USER / MAIL_PASS. A diagnostic endpoint at /diag/email?to=you@example.com lets SuperAdmin test delivery without writing code.

On Registration
QR Ticket Email
Sent immediately when a participant registers. Contains event details, QR code, venue & time.
24 Hours Before (Celery Beat)
Participant Reminder
Automated day-before reminder with QR ticket re-attached. WhatsApp message also sent if phone on file.
24 Hours Before (Celery Beat) — NEW
Coordinator Briefing
All assigned coordinators get event details, participant count, and a day-of operations checklist. Sent once per event via coord_briefing_sent flag.
Coordinator Assignment
New Account Credentials
When SPOC assigns a new coordinator, an email is sent with auto-generated login password and link to the portal.
On Password Reset Request
Password Reset Link
Secure time-limited token (1 hour) sent via itsdangerous. SuperAdmin excluded from this flow — uses master key instead.
Post-Event
Certificate Ready
After SPOC publishes results, winners and participants receive email notification that their certificate is available.
SPOC Triggered
Blast Email
SPOC can compose and send custom HTML email to all registrants of any of their events.
Manual (Admin/SPOC)
Reminder Trigger
Admin or SPOC can manually trigger the reminder send for any event outside of the automated schedule.

Security & Authentication
How the platform keeps accounts and data safe
LayerImplementation
Password HashingWerkzeug scrypt/pbkdf2 — no plaintext passwords stored. Legacy plaintext rows are blocked at login and flagged for admin reset.
CSRF ProtectionFlask-WTF CSRF tokens on all POST forms; automatic 400 on mismatch
SuperAdmin Master KeyExtra secret key required at login in production mode — prevents brute-force account takeover even with correct password
Password Reset Tokensitsdangerous URLSafeTimedSerializer; tokens expire after 1 hour; one-time use
Forced Password ResetAuto-generated accounts get needs_password_reset: true — user must change password on first login
Role-Based Access@role_required decorator on every protected route; session cookie checked on every request
Security HeadersX-Frame-Options, X-Content-Type-Options, CSP, HSTS set on every response via after_request hook
Rate LimitingFlask-Limiter on login and registration endpoints — 429 returned on abuse
Secure SessionSESSION_COOKIE_HTTPONLY=True, SESSION_COOKIE_SAMESITE='Lax', permanent sessions with configurable TTL
Enum-safe Role NormalizationLegacy 'Coordinator' → 'EventCoordinator' and 'Super Admin' → 'SuperAdmin' on every login path

Section 10
Bug Fixes Log
Every issue resolved, with root cause and solution
🔴 EventCoordinator Login Always Failing (POST /login → redirect loop)
routes_spoc.py · routes_auth.py · routes_coordinator.py
Root Cause: Three-file cascading mismatch. When SPOC assigns a coordinator, the account was created with role: 'Coordinator' in Firestore. But the login form sends role='EventCoordinator'. The auth check db_role != role fails every time.

Cascading Effect: Even if user manually changed DB role to EventCoordinator, the coordinator dashboard's COORD_ROLES list didn't include it, so they'd be denied access after login.

Fix: Changed account creation to use 'EventCoordinator', added legacy normalization in auth, and added 'EventCoordinator' to COORD_ROLES.
- 'role': 'Coordinator' # wrong — login would always fail + 'role': 'EventCoordinator' # matches login form value - if db_role == 'Super Admin': db_role = 'SuperAdmin' + if db_role == 'Super Admin': db_role = 'SuperAdmin' + if db_role == 'Coordinator': db_role = 'EventCoordinator' # legacy normalization
🔴 /spoc/api/coordinators — 500 AttributeError: 'dict' object has no attribute 'to_dict'
routes_spoc.py · api_coordinators()
Root Cause: Overcomplicated double-comprehension was calling .to_dict() on an already-converted dict: [... for doc in docs for d in [doc.to_dict() or {}]] — the inner loop variable d is a plain dict, not a Firestore document, so d.to_dict() crashes.

Additionally, the query was filtering for role == 'Coordinator' but the correct role is now 'EventCoordinator'.
- docs = db.collection('users').where('role', '==', 'Coordinator').stream() - result = [{'email': (d.to_dict() or {}).get(...)} for doc in docs for d in [doc.to_dict() or {}]] + docs = db.collection('users').where('role', '==', 'EventCoordinator').stream() + result = [{'email': (doc.to_dict() or {}).get('email', doc.id), 'name': ...} for doc in docs]
🔴 /spoc/announcements/public/<id> — 500 FailedPrecondition: Query requires an index
routes_spoc.py · public_announcements()
Root Cause: Firestore requires a manually-created composite index for queries that combine a WHERE clause on one field with ORDER BY on a different field. The query had where(event_id == x).order_by(timestamp) but no composite index existed in Firebase console.

Fix: Removed .order_by() from the query; sort in Python after fetching.
- .where(filter=FieldFilter('event_id', '==', event_id)) - .order_by('timestamp', direction='DESCENDING') - .limit(20).stream() + .where(filter=FieldFilter('event_id', '==', event_id)) + .limit(20).stream() + items.sort(key=lambda x: x['ts'], reverse=True) # sort in Python
🟡 Jinja2 UndefinedError: 'today_events' is undefined
templates/coordinator/scanner_selector.html
Root Cause: Template was updated to expect today_events / tomorrow_events / upcoming_events variables, but the route function was still passing the old events=events single list. Server hadn't been restarted, so the new route code wasn't active.

Fix: Confirmed route was updated correctly; required server restart to reload new Python code.
🟡 Participant Dashboard Showing Past Events in "Upcoming" Section
routes_participant.py · dashboard()
Root Cause: The upcoming events query fetched all active events regardless of date. Events from months ago appeared in the "Browse & Register" section.

Fix: Added date filter — skip any event where date < today.
+ today = datetime.date.today().strftime('%Y-%m-%d') + if d.get('date', '9999-99-99') < today: continue
🟢 app.py Redundant upcoming List (Code Quality)
app.py · home()
Issue: A upcoming = [d for d in events if d.get('date') >= current_date] re-filter was applied after events was already filtered by the same continue guard in the loop above — pure redundant work.

Fix: Removed the intermediate list; iterate events directly.
🟢 Dead Jinja2 'is defined' Guards on FirebaseWrapper Objects
templates/public/home.html
Issue: Templates had patterns like ev.title if ev.title is defined else ev.get('title',''). FirebaseWrapper objects always have these attributes — the fallback branch was unreachable dead code.

Fix: Removed all such guards; simplified to ev.title directly.
🟢 cat_icons Dict Re-defined Inside Loop (Efficiency)
templates/participant/dashboard.html
Issue: The {% set cat_icons = {...} %} dictionary was inside a {% for _ in range(2) %} loop (for the infinite ticker), so it was re-created twice per page render.

Fix: Moved the dict definition to before the loop.
🟢 index.html — JS onclick Missing Quotes Around event.id
templates/index.html · line 727
Issue: onclick="showEventModal({{ event.id }})" — Firestore document IDs are strings (e.g. abc-123). Without quotes, the JS engine sees hyphens as subtraction operators → parse error.

Fix: onclick="showEventModal('{{ event.id }}')"
🟢 Empty CSS Rulesets in index.html
templates/index.html · lines 285, 349
Issue: .modal-header .btn-close{} and .ev-card{} were empty rules flagged by VS Code CSS linter.

Fix: Added filter:invert(1) to .btn-close (so it shows on dark modal header); removed the empty .ev-card rule.

Database Structure
Firebase Firestore collection schema
📦
events
One document per event
  • title, date, time, venue, category
  • status (active/inactive), is_featured
  • description, rules, agenda[], prizes{}
  • registration_count, limits{}
  • spoc_id, spoc_name, spoc_email
  • staff[] (assigned coordinators)
  • banner_url, whatsapp_group
  • 24h_reminder_sent, coord_briefing_sent
  • openhall_mode, results_published
📋
registrations
One document per participant+event
  • event_id, event_title, event_date
  • participant_email, participant_name
  • usn, phone, college
  • status (confirmed/waitlist/cancelled)
  • checked_in (bool), check_in_time
  • position/rank (after results)
  • ticket_sent, reminder_sent
  • form_data{} (custom fields)
👤
users
One document per user (keyed by email)
  • email, name, phone, usn
  • role (Student/EventCoordinator/etc.)
  • category (club/dept)
  • password (hashed scrypt/pbkdf2)
  • needs_password_reset (bool)
  • created_at
📢
announcements
Live event updates
  • event_id, event_title
  • message, priority (urgent/info/success)
  • timestamp
  • posted_by (SPOC email)
📝
feedback
Post-event participant ratings
  • reg_id, event_id
  • rating (1-5), comment
  • submitted_at
📊
action_logs
Audit trail for all actions
  • action (LOGIN, REGISTER, etc.)
  • detail
  • timestamp
